# 01 · 项目约章（Project Charter）

## 目标与优先级

1. **个人高质量 SQL IDE**：以 VS Code 风格为默认交互，日常高频操作流畅、安全、可靠。
2. **学习 IDE 核心**：系统掌握 Workbench、DI/Contribution、Editor、LSP、Extension Host、Electron 构建与进程管理。
3. **开源工程质量**：维护清晰、可回归、上游升级可控；欢迎外部贡献但不以活跃用户数为主要衡量。
4. **长期实验**：独立研究 Tauri/轻量化/SQL Agent；实验失败不影响主线。

## 核心用户

- 主要用户：项目作者本人、日常写 SQL 的前后端开发者。
- 次要用户：愿意使用开源工具的开发者。
- **非目标**：短期内全面替代 DataGrip/DBeaver 的所有 DBA 功能，企业多租户管理平台，云上共享数据库代理，数据库监控 SaaS。

## 成功指标（质量而不是营销）

- 首个 0.1 MVP：至少连续 7 个真实工作日能够完成 SQLite 连接与查询操作，不依赖旧 SQL GUI 完成相同任务（只针对已经支持的操作）。
- 0.2：能在 PostgreSQL 完成数据库树、SQL 执行、取消、结果导出、基础执行计划。
- 0.3：能够安全恢复会话、诊断断线/长查询、完成 MySQL 基础闭环。
- 每个里程碑都有一篇源码机制笔记、一个可复现测试、一个架构复盘。
- 平台工程：从相邻 Code OSS 稳定 Tag 升级一次，记录实际冲突与回归工时。

## 非目标清单（初期不做）

- VS Code 全功能裁剪/完全复刻 Tauri。
- 自动执行 AI 编写的生产库 DDL/DML。
- 多数据库同步/通用数据迁移引擎。
- ER 绘图、可视化建模、数据库审计平台、团队协作 SaaS。
- 兼容所有 VS Code Marketplace 插件（兼容 API 不代表任何插件/市场都有合法分发和可用性）。
- 性能 KPI 不以未经测量的“启动 0.2 秒/50MB”作为承诺。

## 产品级约束

- Desktop-first：Windows x64、macOS arm64；Linux 后续。
- SQL-first：无 Folder Workspace 也可使用；数据库账号凭证不写到工作区。
- Rust Core 不依赖 Electron/Tauri API，驱动差异显式表达。
- Code OSS 核心层保留上游历史，非必要不改 `base`、`platform`、`editor`。
- 对数据库执行、日志、Agent 工具坚持默认最小权限。

## 验证顺序

首要问题不是“好不好看”，而是：① Code OSS 基线能否可维护地派生；② SQL 执行闭环是否正确、安全；③ Workbench/扩展集成能否完成自身学习目标；④ UI 体验是否比现有个人工具更符合习惯。

## 约束变化流程

新的需求先判断是核心体验、学习实验还是范围扩张；记录一个 ADR。若导致 P0–P2 超出容量，必须移走同等规模的低优先级任务。禁止靠堆 TODO 吞并不确定性。
