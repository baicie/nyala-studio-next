# 02 · 产品规格与核心使用故事

## 0.1 MVP（最小但完整）

1. 启动 Nyala → 默认显示 SQL Connections（首次使用展示连接引导），不要求选择文件夹。
2. 添加一个 SQLite 文件或内存连接，显示连接状态，凭证（未来数据库）绝不持久化为明文。
3. 左树查看表、视图和列；树节点显示加载、错误、无权限、空状态。
4. 打开一个 SQL Editor Tab；选择连接；输入 SQL；`Ctrl/Cmd+Enter` 执行当前语句或选区；明确执行按钮。
5. Result 面板展示列、数据、影响行数、耗时、错误；可以复制，数据量超出限制有提示。
6. 点击取消；对于无法中断的后端，显示 `Cancel Requested` 和最终确定状态，不作成功承诺。
7. SQL 草稿与非敏感历史持久化，可恢复 SQL 内容与连接身份，但不会自动重放查询。
8. 只读连接真正使用驱动/数据库级约束；拒绝不被授权的修改，且说明限制范围。

## 基础角色 / Jobs To Be Done

- **日常开发者**：我想几秒内找到表、写 SQL、查结果，不在界面中穿梭。
- **调试者**：我希望知道当前查询属于哪个连接/Schema，断线/超时原因明确。
- **学习者**：我想看到 IDE 中每个功能对应的 Workbench / RPC / Rust 模块。

## 0.2 迭代

- PostgreSQL 驱动（密码、TLS、Schema、取消、只读策略、Explain）优先；真实数据库 fixture。
- 表/列补全，至少在元数据缓存可用时工作。
- Result Grid 支持虚拟滚动、复制范围、CSV/JSON 导出（有导出阈值和风险提示）。
- 工作区恢复与多个编辑器独立连接上下文。

## 0.3 迭代

- MySQL 驱动与类型语义；连接错误/SSL；会话变量与事务差异。
- SQL 脚本拆分与语法错误定位；Explain UI；查询历史检索。
- 更专业的 Grid：列宽、固定列、NULL、长文本/JSON 可视化。

## 0.4+ 候选（不应阻塞主线）

- SQL Performance Lab（SQL/Plan 两版本比较与证据留存）。
- Agent：基于受控的数据库工具接口操作，不自动执行写操作。
- 第三方驱动 SPI、SSH Tunnel、结构 Diff、Data Editor（需乐观锁/主键验证）、Tauri 实验。

## 非功能性验收

- 输入焦点、键盘快捷键、Editor 分组符合 VS Code 用户的预期。
- 每一次 SQL 执行有可识别 `executionId`、终态及稳定错误信息。
- 不允许从一个 Tab 的连接切换影响另一个 Tab 的事务或查询。
- 10 万行测试不允许一次创建 10 万个 DOM 行；大结果以内存上限和分页/游标机制保护。
- 记录真实测试机器/系统/数据库版本，避免把工程目标写成已经测量的结果。

## UX 验收样例

- 打开 `users` 表 → 打开查询 → 执行无 WHERE 查询 → UI 显示默认行数上限，不静默读取整个大表。
- 在 A 连接执行查询时切换到 B 连接，不得让 A 的执行结果重绑定 B。
- SQL Tab 带未保存标记；重启只恢复查询文本，不重新执行 DML。
- 编辑器双分屏时两个独立 Tab 各显示自己的数据库连接标识。

## 竞争与个性边界

可以借鉴 DataGrip / DBeaver / Beekeeper Studio 的交互体验，但不以支持数据库数量、AI 聊天入口或营销差异化作为首发目标。重点是 VS Code 手感、正确的 SQL 上下文、可靠执行与清晰的 UI。
